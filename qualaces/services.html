Core test types

Smoke Testing

Confirms the most critical functionality works.

Smoke testing is done to ensure that the most critical functionalities of a system are working fine. It is the quick check that tells you whether a build is stable enough to be worth testing any further.

Typical use
Every new build or deployment.

Core test types

Sanity Testing

A focused check after a small change.

Sanity testing is a type of software testing done after a minor change in the code or functionality to ascertain that the bugs have been fixed. It stays narrow on purpose: verify the fix, check its neighbours, move on.

Typical use
Right after a bug fix or a minor change.
Pairs well with
Smoke TestingTicket Testing

Core test types

Regression Testing

Exhaustive re-testing when software changes.

Regression testing is exhaustive testing that is conducted when changes or enhancements are made to the software. It exists to catch the thing a new feature quietly broke somewhere else.

Typical use
Before a release, or after larger changes.
Pairs well with
Automation TestingSmoke Testing

Core test types

Ticket Testing

Verifies individual items from your issue tracker.

Ticket testing involves testing individual items, or 'tickets', that are part of an issue tracking system. Each ticket is verified against what it said it would deliver, so the tracker reflects reality.

Typical use
Sprint close, or when a backlog of fixes needs sign-off.

Automation Testing

Automated checks with minimal developer involvement.

Automation testing is a method where the computer runs many tests on different software components with little to no developer participation. Any software you use daily, from what runs your phone to your TV or even your car, had to pass a predetermined process before it reached users. Automation makes that process repeatable.
